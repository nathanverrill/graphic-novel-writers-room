03Rules of the book

  1. Bob's words are never changed. No rewording, no punctuation or typo cleanup, no canon fixes. Where canon disagrees with Bob, flag it to the showrunner. Only an explicit showrunner decision overrides (recorded in rules/decisions.md).
  2. Version on feedback. Before applying script feedback, snapshot the drafts to drafts/_versions/vN. Versions continue Bob's numbering. The shared script doc is titled "Prosperity Script" with the line "Version N · timestamp" under it.
  3. Art is drawn by GPT Image 2.5 Sunburst (openai/gpt-image-2.5-sunburst), never Gemini.
  4. Art is reviewed by Gemini 4 Argon (google/gemini-4-argon) against the checklist below, and then by a person.
  5. The Charter Houses are Helion (deep amber-orange), Aqualis (cool jade-teal) and Astra (pale steel-violet).

The standing art checklist

Every item is a must-fix. New kinds of mistake go into ALWAYS in app/artcheck.py and rules/art-checklist.md, so they are both prevented in the drawing prompt and caught in review.

  • One left hand on the left arm, one right hand on the right arm, five fingers. Never two right hands.
  • Nobody balances on a railing, floats or passes through things.
  • Speakers face and look at whoever they talk to; no awkward looks.
  • Photos, papers and screens a character looks at face the character, not the reader.
  • No body part beside another character's face; two-shots are face to face.
  • People who are together stay together.
  • Light, place and mood hold through one continuous moment.
  • The setting and tone match the script (the home stays the home; hard times are not drawn happy).
  • Characters match their locks; the daughter is never drawn as Ada.
  • Lettering: tails point at the speaker, nothing covers any part of a face, no invented text, every word exact.

04Changing the script

Small edits, directly

  1. Open the file browser and go to campaigns/prosperity-book/drafts/.
  2. Copy the current drafts into a new _versions/vN/ folder first.
  3. Edit the chapter file. Keep the page headings (## PAGE 7: TITLE) and the panel labels (**P1**, **P2** …); the page tools read them.
  4. Rebuild the layouts (section 08), then redraw only the pages that changed (section 09).

Feedback through a shared Google Doc

  1. The script goes into one Google Doc, "Prosperity Script", with "Version N · timestamp" under the title. The same doc is kept across versions.
  2. Bob edits and comments in the doc.
  3. Ask Claude to read the doc's edits and comments into the drafts. It snapshots a new version first, applies Bob's edits word for word, and lists every comment that needs a decision.
  4. Rebuild layouts and redraw the affected pages.

05Running the room

The room is the web app. For Prosperity it runs in edit mode: Bob's drafts are the script, so the room brings them into the canon rather than writing new ones.

  1. Pre-production (/preproduction): press Run intake. Answer the open items it raises (approve, edit, defer or leave), press Update canon, answer what is left, and update again.
  2. Before approving, open the Story desk (/story): the outline as a board, a structure check against the hero's journey, the character locks beside their descriptions, and Riff for brainstorming edits section by section.
  3. Approve by typing evoke. Check that approval succeeded before going on; a failed approval leaves production on the old canon.
  4. Production (/production): one button runs development, the draft edit and the pages. Settings live in production/round-settings.json (62 pages, draft_mode: "edit", at most 7 panels and 3 characters a panel).
Two known problems in edit mode. The room's Draft Editor has reworded Bob's lines, and its writer stopped at 41 of 62 pages. For this book the draft edit is bypassed (draft.md copied to draft-edited.md and draft-final.md) and the layouts come from the deterministic tool in section 08, not the room's Layout Agent.

06Character locks

A lock is the reference drawing every page uses for a character. The pages match a lock by its folder name.

  1. Draw or redraw locks in Easel (easel/ in the repo; Sunburst only) or with Redraw on the Story desk's Locks tab.
  2. Save the chosen image as style/locks/<name>-sunburst/lock.png. Move the old one into previous/ beside it.
  3. Props (the watch, the pump) go in style/props/; the overall look is style/plate.png.
  4. Redraw any page the change affects.

07Page tools: setup

The finished pages are made with five scripts in tools/, run on Nathan's laptop from the repo root. They talk to OpenRouter directly; the room does not need to be running.

ScriptDoes
repage.pyMoves page breaks only, so no page is crowded (at most 130 words, 6 panels). Refuses to save if any line changed
drafts2layouts.pyTurns the drafts into layouts.md, word for word
book_pages.pyDraws pages: art with no lettering → art check → SVG overlay → image-model lettering
reletter.pyLetters existing art again, without redrawing it
qa_fix.pyThe strict Argon review, with up to 3 rounds of automatic fixes
make_pdf.pyCompiles the lettered pages into one PDF

Open a terminal in the repo and set these once per session. The three addresses switch off services the scripts do not need.

cd ~/writers-room
export OPENSEARCH_URL=http://127.0.0.1:1 OLLAMA_URL=http://127.0.0.1:1 S3_ENDPOINT=
T=campaigns/prosperity-book/tools
L=campaigns/prosperity-book/production/layouts.md

The OpenRouter key is read from OPENROUTER_API_KEY if set, otherwise from secrets/keys.json, where the room saves the key pasted into its settings.

08Drafts to layouts

  1. If a chapter feels crowded, repaginate it. This only moves page breaks: 
    .venv/bin/python $T/repage.py campaigns/prosperity-book/drafts/01-chapter-01.md
  2. Back up the current layouts, then rebuild them from all four drafts: 
    cp $L $L.bak
.venv/bin/python $T/drafts2layouts.py $L
  3. The alternate pipe ending gets its own layouts file. Pass the file and FIRST, the book page number its first page should take (the Chapter 2 page where the endings split): 
    .venv/bin/python $T/drafts2layouts.py campaigns/prosperity-book/production/layouts-pipe.md alt/02-chapter-02-pipe-ending.md FIRST
Hand edits are overwritten. Rebuilding replaces any edits made directly in layouts.md (for example the prologue's page 3 and 4 descriptions). The prologue is drawn from tools/prologue-layouts.md, which the rebuild does not touch.

09Drawing pages

Each page costs about $1–2 and takes 5–15 minutes. Several pages run side by side.

  1. Back up the pages you are about to replace: 
    R=campaigns/prosperity-book/renders/sunburst; mkdir -p $R/_v7
for n in 07 08; do cp $R/art/p$n.png $R/_v7/art-p$n.png; cp $R/lettered-model/p$n.png $R/_v7/lettered-model-p$n.png; done
  2. Draw. PAGES is a comma list; WORKERS is how many at once: 
    PAGES=7,8 LAYOUTS=$L WORKERS=2 .venv/bin/python $T/book_pages.py
  3. For the prologue, use its own layouts: 
    PAGES=1,2,3,4 LAYOUTS=$T/prologue-layouts.md WORKERS=4 .venv/bin/python $T/book_pages.py
  4. Each page prints one line: page, cost, whether the art and lettering passed the art check, and what was flagged.
  5. Results land in renders/sunburst/: art/pNN.png, overlay/pNN.svg, lettered/pNN.png (SVG lettering) and lettered-model/pNN.png (the final page).
  6. Look at every page yourself before showing it to anyone.

10Fixing a page with notes

Notes are short JSON files keyed by page number. NOTES changes the drawing; LNOTES changes the lettering. EARLIER points at a backup folder so the redraw keeps the old page and changes only what the notes say.

  1. Write the notes. Name the panel, what is wrong, and what it should be: 
    cat > /tmp/notes.json <<'JSON'
{"8": "PAGE 8 (overrides below): keep the attached earlier version except: panel 1 Alex holds the photograph facing HIMSELF; panel 4 is a close two-shot, face to face at eye level."}
JSON
cat > /tmp/lnotes.json <<'JSON'
{"8": "Every balloon sits above or beside heads, never over a face. Panel 2's lines are ALEX's."}
JSON
  2. Redraw against the backup from section 09: 
    PAGES=8 EARLIER=sunburst/_v7 LAYOUTS=$L NOTES="$(cat /tmp/notes.json)" LNOTES="$(cat /tmp/lnotes.json)" .venv/bin/python $T/book_pages.py
  3. If only the lettering is wrong, keep the art and re-letter (about $0.20): 
    PAGES=8 LAYOUTS=$L LNOTES="$(cat /tmp/lnotes.json)" .venv/bin/python $T/reletter.py

Saved examples are in tools/notes/. If a line is spoken by the wrong character, say who speaks it by appearance ("ALEX, black wavy hair"), since the image model goes by what it sees.

11Art QA

qa_fix.py asks Gemini 4 Argon to check a page against the checklist. If it finds problems, it redraws or re-letters with the problems named, then checks again, up to three rounds. It overwrites the page files in place, so back up first.

mkdir -p $R/_preqa2 && cp $R/lettered-model/p*.png $R/_preqa2/
PAGES=5,6,7 LAYOUTS=$L .venv/bin/python $T/qa_fix.py 2>&1 | grep --line-buffered -v Warning | tee qa.log

Each page prints page cost [(art, lettering) per round] [problems left]. (0, 0) in the last round means clean.

What we learned. Whole-page redraws trade one mistake for another: after three rounds, 13 of 58 chapter pages came out clean, at about $140. Fixing one panel at a time and using the SVG lettering layer on pages that still fail are the next steps. Keep --line-buffered, or the log shows nothing until the run ends.

13Updating the room on GCP

The VM runs the prosperity-showrunner branch, which has the showrunner reading room and other features not on main. New work goes onto main first, then main is merged into that branch.

  1. Commit and push the code and text. Images, PDFs and call logs stay out: 
    git add app easel agents tests README.md campaigns/*/drafts campaigns/*/rules campaigns/*/production/*.md campaigns/prosperity-book/tools
git status --short | grep -E '\.(png|jpe?g|pdf|svg)$'   # should print nothing staged
git commit -m "What changed"
git push origin main
  2. Merge main into the VM's branch and push it. If git reports a conflict, resolve it before pushing: 
    git fetch origin
git worktree add /tmp/wr-showrunner origin/prosperity-showrunner -b showrunner-merge
cd /tmp/wr-showrunner && git merge origin/main && git push origin showrunner-merge:prosperity-showrunner
cd ~/writers-room && git worktree remove /tmp/wr-showrunner && git branch -D showrunner-merge
  3. Pull on the VM: 
    gcloud compute ssh writers-room --zone us-central1-a --command "cd /home/nathan/writers-room && sudo -u nathan git pull --ff-only"
  4. Copy locks, props and the plate (not in git): 
    tar --exclude='*/previous/*' -czf /tmp/style.tgz campaigns/prosperity-book/style
gcloud compute scp /tmp/style.tgz writers-room:/tmp/style.tgz --zone us-central1-a
gcloud compute ssh writers-room --zone us-central1-a --command "sudo tar -xzf /tmp/style.tgz -C /home/nathan/writers-room && sudo chown -R nathan: /home/nathan/writers-room/campaigns/prosperity-book && rm /tmp/style.tgz"
  5. Rebuild and restart. The room is down for a few minutes: 
    gcloud compute ssh writers-room --zone us-central1-a --command "cd /home/nathan/writers-room && sudo docker compose -f docker-compose.yml -f deploy/gcp/caddy.yml up -d --build && sudo docker compose -f docker-compose.yml -f deploy/gcp/caddy.yml restart caddy"
  6. Open the room and sign in to check it loads.

Setting up a VM from nothing: deploy/gcp/deploy.sh creates the IP, firewall, VM, HTTPS and password, and prints the address.

14Adding or removing a login

Logins are lines in deploy/gcp/Caddyfile on the VM, one under each basic_auth { block (the room and the file browser). Each line is a user name and a password hash.

  1. Add a user (replace NAME and PASSWORD): 
    gcloud compute ssh writers-room --zone us-central1-a --command '
cd /home/nathan/writers-room
H=$(sudo docker run --rm caddy:2 caddy hash-password --plaintext "PASSWORD")
sudo sed -i "/basic_auth {/a\        NAME $H" deploy/gcp/Caddyfile
sudo docker compose -f docker-compose.yml -f deploy/gcp/caddy.yml restart caddy'
  2. Remove a user, for example Bob: 
    gcloud compute ssh writers-room --zone us-central1-a --command '
cd /home/nathan/writers-room
sudo sed -i "/^ *bob /d" deploy/gcp/Caddyfile
sudo docker compose -f docker-compose.yml -f deploy/gcp/caddy.yml restart caddy'
